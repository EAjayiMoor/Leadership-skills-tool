# 2 Design

## Purpose

Turn the agreed first slice into an understandable user journey, defensible assessment method and implementable system design.

## Required work

- Map the journey from engagement setup to report approval, including errors and review checkpoints.
- Define the data model: engagement, participant group, question set, response, source evidence, theme, finding, approval and output.
- Define provenance from every published finding to permitted supporting evidence.
- Agree heatmap meaning, categories, aggregation, uncertainty and review process before designing its display.
- Agree roles and permissions for raw evidence, working findings and approved reports.
- Choose input schemas, output formats, hosting boundary and AI-processing boundary.
- Prototype key screens with assessment users and revise from observed usability issues.
- Record trade-offs and security/privacy assumptions in decision records.

## Exit evidence

- Reviewed journey and screen flows, including onboarding and import failures.
- Agreed assessment and heatmap method, with examples.
- Data and permissions model, including client separation and retention rules.
- Architecture and threat review appropriate to the chosen data environment.
- Acceptance examples for the first slice and a test plan.

## AI use

AI may generate design alternatives and prototypes. Subject-matter and governance owners approve the assessment method, permissions and client-facing interpretation.
