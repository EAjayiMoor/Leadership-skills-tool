## Global Constraints

- Use synthetic reference-shaped, large pharma and energy and utilities scenarios; exclude shared source records.
- Run on a local Next.js development server. Application persistence, import, synthesis, authentication and report generation are outside Sprint 1.
- Primary navigation is a side panel with Overview and seven stages; compact it into an accessible menu at narrow widths.
- Both themes are required, following system preference by default with a manual selection.
- Follow the Moorhouse UI Standard, British English and sentence case; target WCAG 2.2 AA.
- Display stage progress separately from content approval. Stage labels are illustrative, not an implemented workflow state machine.
- Use the neutral text title “Assessment workspace”; the approved logo and product name are pending.
- Keep unfinished operations visibly labelled as prototypes. Export remains unavailable in Sprint 1.
- Preserve existing documentation changes. Do not push, publish or commit identifying source material.

## Review Focus

- Direct navigation to an unknown scenario or stage must show a usable not-found page, rather than another scenario's data (Task 1 browser cases).
- System theme, manual override and unavailable preference storage must leave content visible without hydration errors (Task 2 browser cases).
- Mobile navigation and long stage names must remain operable with keyboard and at narrow widths (Task 1 and Task 4 browser cases).
- Dense source excerpts and long synthetic names must reflow without hiding source attribution (Task 3 browser cases).
- A visible approved example must never enable an export or suggest real publication occurred (Task 3 browser cases).
